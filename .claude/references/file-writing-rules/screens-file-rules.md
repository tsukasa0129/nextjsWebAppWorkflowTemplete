# 画面要件の指示書の記述ルール

## アウトプット先
`/{output-directory}/docs/screens/screens-summary.md`
`/{output-directory}/docs/screens/u-{N}/spec.md`
`/{output-directory}/docs/screens/u-{N}/screen.png`


## 記入フォーマット
### `screens-summary.md`

画面構成を一覧で記述する。

```markdown
# 画面構成

## ユーザー画面
| 画面ID | 画面名 | 概要 |
|--------|--------|------|
| U-001  | {画面名} | {概要} |

## 管理画面（該当する場合）
| 画面ID | 画面名 | 概要 |
|--------|--------|------|
| A-001  | {画面名} | {概要} |
```

### `spec.md`

画面の詳細を記述する。以下のセクションを順番に含める。

```text
1. 基本情報
2. 目的
3. 表示要素の詳細
4. 状態
5. バリデーション
6. 画面遷移
7. アニメーション
8. SEO / メタ情報
9. GA4 イベント
```

記述ルール:

- 冒頭の見出しは `# {画面ID}: {画面名}` とする
- 基本情報は表形式で、画面ID・画面名・パス・認証要否・関連機能IDを記載する
- 表示要素はセクション（ヘッダー / ヒーロー / フッター等）ごとに分けて箇条書きで記述する
- 状態は「通常 / ローディング / エラー」を最低限カバーする
- 入力フォームがない画面はバリデーションを「なし」と明記する
- 画面遷移は遷移方向・遷移先・トリガーを表でまとめる
- 関連機能ID（F-xxx）がある場合はリンクで繋げる

```markdown
# {画面ID}: {画面名}

## 基本情報

| 項目 | 内容 |
|------|------|
| 画面ID | {画面ID} |
| 画面名 | {画面名} |
| パス | `{URLパス}` |
| 認証 | 必要 / 不要 |
| 関連機能ID | {F-xxx（機能名）} |

## 目的

{この画面が達成すべきこと。ユーザー行動の目標やKPIがあれば記載する}

## 表示要素の詳細

### {セクション名（例: ヘッダー）}

- {表示要素・コンポーネント}
- {スタイルや挙動の補足（例: CTAボタンはオレンジ背景 `bg-orange-500`）}

### {セクション名（例: ヒーローセクション）}

- {メインヘッドライン・サブヘッドライン・CTA等}

### {セクション名（例: フッター）}

- {利用規約・プライバシーポリシー等のリンク}

## 状態

### 通常状態

- {通常時の表示内容}

### ローディング状態

- {ローディング時の挙動。SSG/ISR等で発生しない場合はその旨を明記}

### エラー状態

- {エラー時の挙動・フォールバック表示}

## バリデーション

- {入力値の検証ルール。フォームがなければ「なし」}

## 画面遷移

| 方向 | 遷移先 | トリガー |
|------|--------|----------|
| {遷移元→遷移先} | `{パス}` | {ボタンクリック等} |

## アニメーション

- {要素ごとのアニメーション（フェードイン・パルス・カウントアップ等）}

## SEO / メタ情報

- `title`: 「{ページタイトル}」
- `description`: 「{メタディスクリプション}」
- OGP画像: {OG画像の指定}

## GA4 イベント

| イベント名 | トリガー | パラメータ |
|-----------|----------|-----------|
| `{event_name}` | {発火条件} | `{param1}`, `{param2}` |
```



### docs/screens/u-{N}/screen.png

OpenAI APIで画面UI画像を生成して配置する。

- モデル: `gpt-image-2`
- プロンプト: エージェントが画面仕様から考える
- サイズ: スマホ画面なら縦長、PC画面なら横長
- quality: `high`
- APIキー: 環境変数 `OPENAI_API_KEY`
- 生成した画像を `screen.png` として保存する
