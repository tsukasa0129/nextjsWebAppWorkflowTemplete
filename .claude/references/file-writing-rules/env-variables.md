# 環境変数指示書の記述ルール

## アウトプット先
`/{output-directory}/docs/env-variables/env-variables.md`


## 記入フォーマット
アプリで使用するすべての環境変数を1ファイルにまとめる。以下のセクションを順番に含める。

```text
1. 概要
2. 環境変数テーブル（一覧）
3. 各変数の詳細
4. 注意事項（セキュリティ）
5. .env.local サンプル
```

記述ルール:

- 開発時は `.env.local`、本番は Vercel 等のホスティング環境変数に設定する前提で書く
- クライアント公開変数は `NEXT_PUBLIC_` プレフィックスを必ず付け、シークレットには絶対に付けない
- シークレット系の変数は「**サーバーサイドのみ**」と明記する
- 取得元（Dashboard のパス等）と利用開始フェーズを必ず記載する
- 関連する user-task / phase がある場合はリンクで繋げる
- プレースホルダー値は実際の値ではなく形式が分かるダミー（`pk_test_...` 等）を使う

```markdown
## 概要
このドキュメントでは、{アプリ名}で使用するすべての環境変数を定義する。
前提としてアプリは全て隔離されたドッカーサンドボックスで開発をする。
開発用の環境変数は、
 - 公開キーは`local.env`で管理。
 - 秘密キーは全て `sbxコマンド` からドッカーサンドボックに注入する。

## 秘密キーの注入コマンド
ホスト側で実行します。

```bash
sbx secret set-custom \
  --sandbox my-sandbox \
  --host api.example.com \
  --env MY_API_KEY \
  --value "$MY_API_KEY"
```

| オプション    | 意味                                                    |
|--------------|---------------------------------------------------------|
| --sandbox    | 対象のサンドボックス名。省略すると全体に適用           |
| --host       | キーの置換対象ホスト。https://やパスは含めない           |
| --env        | サンドボックス内に設定する環境変数名                    |
| --value      | 実際のAPIキー。上の例ではホストの環境変数から取得        |

## 注意事項

### セキュリティ

- `NEXT_PUBLIC_` プレフィックスが付いた環境変数は、ビルド時にクライアントサイドの JavaScript バンドルに埋め込まれる。シークレットキーには**絶対にこのプレフィックスを付けない**こと
- 以下の変数はサーバーサイド専用のため、特に注意が必要:
  - `{SERVER_ONLY_KEY_1}`
  - `{SERVER_ONLY_KEY_2}`
